# 무야호농장 개선 작업 인계서

이 문서는 현재 저장소를 처음 보는 AI가 무야호농장의 그래픽, 조작, 반복 플레이를 개선할 때 사용할 작업 명세다. 아래 목록은 제안이며, ★는 특히 효과가 클 것으로 보는 항목이다.

> 이 저장소와 인계서를 먼저 읽고, 현재 구현에서 이미 충족된 항목을 확인해 주세요. ★ 항목과 겹치는 기능은 기존 구현을 발전시키고, 나머지 항목도 각자 맡은 파일과 검수 조건을 기준으로 진행해 주세요. 범위와 배포 여부는 이 문서와 함께 전달한 제 요청을 따라 주세요. 마무리할 때 실제로 검증한 항목과 남은 항목을 나눠 알려 주세요.

## 게임의 방향

일상에 지친 직장인이 잠깐 접속해 심고, 수확하고, 팔고, 농장을 자기 취향대로 키울 수 있는 3D 게임이다. 농장 전체가 화면을 채우며, 플레이어는 밭과 건물을 직접 만진다. Hay Day 레퍼런스에서 참고할 것은 사선 카메라, 길로 연결된 농장 구도, 화면 가장자리의 작은 도구, 행동에 반응하는 오브젝트다. 무야호농장의 고유한 이름, 그래픽, 아이콘, 대사를 사용한다.

- **2분 플레이 예시.** 접속해서 익은 밀밭을 훑어 수확하고, 닭장 달걀을 챙기고, 단골에게 밀을 보낸다. 트럭이 떠나고 판매한 돈으로 입구에 울타리를 놓는다. 다음 접속에 울타리와 남은 작물이 그대로 있다.
- **15분 플레이 예시.** 연못 옆 땅을 열고, 목장을 옮긴 뒤 길과 울타리로 연결한다. 완성한 구역의 대표 사진을 남기고, 다음 주문에 쓸 작물을 심는다.
- **선택의 기준.** 시각 개선은 눌러야 할 곳과 작물 상태를 더 읽기 쉽게 만든다. 장기 콘텐츠는 선택과 애착을 늘리고, 접속 횟수나 반복 클릭으로 플레이를 강제하지 않는다.

현재 지도는 48×48이며 12×12 구역부터 시작한다. 이미 시설 자유 배치·이동·회전·보관·실행 취소, 밭·길·울타리 여러 칸 배치, 구역 확장, 구역 수확, 농장 방문, 사진, 작물 성장과 타이머, 날씨와 소리, 자동화 기능이 있다. 주문은 네 가지 고정 주문을 완료하면 같은 구성이 다시 채워진다. 아래 항목을 시작하기 전에 최신 체크아웃에서 이 상태와 관련 테스트를 확인한다.

## 작업 중 유지할 조건

- 가입은 ID/PW를 사용하고 별도 개인정보를 받지 않는다. 처음 농장을 만들 때 지은 이름을 농장과 브라우저 제목에 표시한다. 예전 저장본처럼 이름이 없는 경우에도 농장을 열 수 있어야 한다.
- 농장 데이터는 현재 Supabase 스냅샷과 서버 명령 흐름을 사용한다. 아이템·코인·주문·배치 변경은 서버에서 검증한다. 중복 요청, 저장 실패, 두 기기 간 충돌에서 아이템 또는 코인이 중복 지급되거나 정상 저장본이 덮이지 않게 한다. 새 필드가 필요한 경우 기존 스냅샷에 적용할 기본값과 읽기 동작을 정한다.
- 자유 배치와 확장, 회전, 실행 취소, 선택한 타일 강조를 보존한다. 빈 타일 안내에 행·열 좌표를 다시 노출하지 않는다. 수확까지 남은 시간은 가까운 화면에서 클릭 없이 확인할 수 있어야 한다.
- 접속하지 않아도 생산이 진행되고, 완성한 생산물은 기다린다. 강제 출석, 연속 접속 보상에 의한 압박, 작물 시듦이나 놓치면 되돌릴 수 없는 행사는 도입하지 않는다.
- 신규·교체 3D 모델은 **모델 파일 자체에 MIT 라이선스 적용이 확인된 공개 에셋**을 사용한다. 코드만 MIT이고 에셋 라이선스가 별도인 경우 모델 기준으로 판단한다. `public/models/sources.json`에 모델의 원본 URL과 해시를 기록하고 라이선스·저작권 고지를 보관한다. 후보가 없으면 기존 모델을 유지하면서 색, 구도, 배치부터 개선한다. 추가 음원과 폰트도 각각의 이용 조건을 확인한다.
- 휴대폰 가로를 주 화면으로 검수하고 세로 화면과 PC에서도 기본 조작을 가능하게 한다. 색만으로 상태를 구분하지 않고, 키보드로 접근 가능한 조작과 기존 움직임·소리 설정을 유지한다.
- 환경변수 값, Supabase 서버 키, 실제 계정 정보는 소스, 테스트, 스크린샷에 넣지 않는다. 테스트용 계정과 저장본을 사용하고 운영 데이터 초기화, 운영 DB 변경, 커밋·푸시·배포는 전달한 작업 범위에 포함된 경우에만 진행한다.

## 조작과 화면

- [x] **★ 첫 카메라 구도** — 농가, 밭, 판매대가 첫 화면에서 크게 읽히도록 프레이밍한다. 줌아웃하면 전체 농장을 볼 수 있고, 집 버튼으로 중심에 돌아온다. 기존 카메라 북마크와 함께 동작하게 한다.
- [x] **★ 농장 오브젝트 직접 조작** — 빈 밭을 누르면 씨앗, 익은 밭은 바로 수확, 판매대는 판매, 창고는 가방 화면을 열 수 있게 한다. 자주 쓰는 선택은 손가락 근처나 하단 짧은 도구 모음에 표시한다.
- [x] **간결한 HUD** — 코인과 핵심 도구만 평소 노출하고 미니맵은 지도 아이콘으로 접는다. 열린 지도에서 구역별 수확 가능 상태를 보여준다. 오브젝트와 타이머를 중요한 순간에 가리지 않게 한다.
- [x] **타이머 가독성** — 가까운 화면에서는 밭을 누르지 않고 남은 시간을 읽는다. 멀리서는 인접한 동일 작업의 타이머를 묶고, 수확 가능 상태는 아이콘과 색으로 나타낸다.
- [x] **★ 쓸어서 심기와 수확** — 씨앗이나 수확 도구를 선택한 상태에서만 드래그로 여러 밭을 처리한다. 같은 밭을 여러 번 통과해도 한 번만 반영하며, 핀치 전환·손가락 취소·카메라 이동이 게임 명령을 잘못 발생시키지 않게 한다.
- [x] **편집 손맛과 안내** — 기존 미리보기와 실행 취소를 활용한다. 배치 미리보기와 확정 상태를 구분하고, 물체가 겹치면 대상과 이유를 해당 위치에 짧게 표시한다. 잠긴 땅, 겹침, 코인 부족을 구분한다.
- [x] **첫 수확 안내** — 첫 농장에 우편함 쪽지로 첫 심기, 수확, 판매를 안내한다. 건너뛰거나 중간에 나갔다 돌아와도 진행을 막지 않는다.

## 그래픽과 월드

- [x] **★ 흙길과 풍경의 구도** — 농가, 밭, 판매대를 흙길로 연결하고 연못, 돌담, 숲 가장자리로 장소를 구별한다. 시작 농장의 조작 동선을 보여주되 장식 때문에 유효한 배치가 막히지 않게 한다.
- [ ] **★ 에셋 크기와 재질 통일** — 문, 울타리, 가축, 판매대의 상대 크기를 정하고 재질의 밝기와 채도를 맞춘다. 표시 크기를 조정하더라도 배치 범위와 클릭 판정을 확인한다.
- [ ] **작물별 실루엣과 성장** — 밀의 이삭, 열매의 위치, 잎의 높이로 작물을 구별한다. 기존 성장 애니메이션을 재사용해 어린 작물과 수확 직전의 차이를 보여준다. 실제 모습과 어긋나는 모델부터 MIT 후보를 확인한다.
- [x] **조명과 그림자** — 나무 아래와 건물 바닥의 접지감을 살리고, 아침과 저녁에도 익은 작물과 빈 밭이 명확히 보이게 한다.
- [x] **잔디와 숲의 반복 줄이기** — 흙길 가장자리와 연못 주변에 색 변화를 주고, 같은 나무도 크기나 방향을 조금씩 달리한다. 화면을 다시 열어도 배치가 흔들리지 않게 한다.
- [x] **가까이서 보이는 생활 흔적** — 창가 화분, 판매대 천, 창고 옆 도구처럼 실제 사람이 쓰는 흔적을 더한다. 장식은 자주 쓰는 상호작용과 경쟁하지 않게 한다.
- [x] **날씨와 시간의 흔적** — 현재 날씨와 조명에 맞춰 비 온 길의 젖은 재질, 바람에 함께 움직이는 깃발과 밀, 저녁 창문 조명을 표현한다. 움직임을 줄이는 설정을 따른다.
- [x] **농장 경계의 선택 폭** — 울타리, 돌담, 생울타리, 좁은 길을 기존 배치·회전 규칙으로 조합할 수 있게 한다. 원경에서 밭 중심과 목장 중심 농장을 구별할 수 있게 한다.
- [x] **대형 농장의 렌더링** — 시작 장면에 필요한 모델을 우선 불러오고 먼 장식, 움직임, 그림자 부담을 줄인다. 기본 농장과 조밀하게 확장한 농장을 모두 열어 시작 시간과 드래그·줌·수확 반응을 비교한다.

## 반복 플레이와 성장

- [x] **★ 주문 구성 개선** — 반복되는 네 주문을 소량 판매, 단골 요청, 장기 주문이 섞이는 구조로 바꾼다. 진행도와 생산 가능한 시설을 기준으로 주문을 골라 불가능한 요청만 쌓이지 않게 한다. 기존 미완료 주문과 공유로 채운 수량을 다루는 규칙을 정한다.
- [x] **★ 복귀할 때 한 줄 요약** — `밀 6칸이 익었고, 닭장에 달걀 2개가 있어요`처럼 지금 할 일을 알린다. 누르면 해당 위치로 이동한다. 준비된 것이 없다면 부담 없는 안내를 사용한다.
- [x] **수확물 활용에 선택 주기** — 밀을 바로 팔거나, 빵으로 가공하거나, 사료로 쓰는 식으로 이미 있는 생산 체인을 연결한다. 재료·시간·보상을 선택 전에 표시한다.
- [x] **확장할 구역마다 다른 매력** — 연못 옆 빈터, 돌담 언덕, 숲 가장자리처럼 다음에 사고 싶은 장소를 보여준다. 구역의 지형은 기억에 남되 유효한 공간은 자유롭게 활용한다.
- [x] **다양한 농장 운영 방식** — 작물 중심, 목장 중심, 꽃과 벌 중심으로 운영해도 판매와 주문을 통해 성장할 수 있게 보상과 해금 구성을 확인한다.
- [x] **넓은 농장의 반복 클릭 완화** — 기존 구역 수확, 스프링클러, 일꾼을 화면에서 발견하기 쉽게 연결한다. 자주 돌보는 곳은 직접, 넓은 곳은 자동화할 수 있게 한다.
- [x] **짧은 목표와 긴 목표 연결** — 당장 살 울타리와 다음에 열 땅처럼 보상과 풍경의 변화를 미리 볼 수 있게 한다. 필요 코인은 실제 구매·확장 규칙과 동일하게 보여준다.
- [x] **작은 발견** — 비 온 뒤 달팽이, 새 구역의 오래된 팻말, 벌통 주변의 나비처럼 관찰하면 보이는 일을 만든다. 한 번 지나쳐도 이후 다시 볼 수 있게 한다.
- [x] **선택형 계절 행사** — 작은 호박 좌판, 꽃 모종 교환대처럼 계절에 농장 풍경이 바뀐다. 구경과 참여 모두 가능하고 핵심 기능이나 성장에 필수 조건을 걸지 않는다.
- [x] **농장 방문의 목적** — 기존 방문·방명록을 활용해 대표 사진과 추천 산책 지점을 공유하고, 마음에 든 구역에 짧은 감상을 남길 수 있게 한다. 방문 권한과 공개 범위는 기존 규칙을 따른다.

## 반응과 애착을 만드는 디테일

- [x] **★ 수확과 판매의 반응** — 이삭이 바구니로 들어가고 판매대에 상자가 놓인다. 납품이 성공하면 트럭이 출발한다. 실패한 명령에는 성공 연출을 재생하지 않고 연속 행동을 가로막지 않는다.
- [x] **농장 이름이 쓰인 입구 팻말** — 기존 농장 이름으로 팻말을 표시한다. 긴 한글 이름, 예전 저장본의 기본 이름, 방문 화면, 사진에서 확인한다.
- [x] **가축마다 다른 반응** — 닭의 흙 쪼기, 소의 고개 돌리기, 돼지의 진흙 놀기처럼 종별 짧은 행동을 넣는다. 기존 동물 이름과 상호작용을 살린다.
- [x] **기억하는 단골** — 반복해서 등장하는 이웃에게 이름과 말투를 준다. “지난번 밀로 아침 빵을 구웠어요”처럼 이전 주문과 이어지는 짧은 대사를 쓴다.
- [x] **재료와 행동에 맞는 소리** — 씨앗, 낫, 울타리, 우유통, 코인 소리를 구분한다. 연속으로 입력했을 때 겹쳐서 커지지 않게 하고 음소거 설정을 유지한다.
- [x] **사진으로 보는 변화** — 첫 수확, 첫 동물, 첫 확장 사진을 기존 사진 기능과 연결한다. 같은 자리에서 현재 모습을 다시 찍어 비교할 수 있게 한다. 사진 저장 위치와 공개 범위를 화면에서 알 수 있게 한다.
- [x] **저장 완료와 오류 표시** — 서버 저장에 성공했을 때만 완료를 알려준다. 연결이 끊기거나 다른 기기와 충돌했을 때는 재시도나 최신 상태 불러오기를 제공한다. 같은 판매를 재시도해도 두 번 처리되지 않게 한다.

## 구현 검수

1. **현재 상태 기록.** 작업 전 동일한 해상도에서 첫 화면과 확장 농장을 기록한다. 기존 로직을 바꾸는 항목은 재현 절차와 기대 동작을 정해 둔다.
2. **새 계정과 기존 계정.** 이름 지정과 제목을 확인하고, 이름 필드가 없는 저장본과 이미 자란 작물이 있는 저장본도 로드한다. 로그아웃 후 다시 들어와 배치, 코인, 수확 상태가 이어지는지 본다.
3. **입력.** 휴대폰 가로와 세로, PC 마우스·키보드에서 드래그, 핀치, 타일 선택, 이동·회전·실행 취소를 확인한다. 연속 수확에서 한 밭을 두 번 지났을 때, 중간에 핀치했을 때, 잠긴 땅을 지났을 때를 각각 확인한다.
4. **게임 규칙과 동시 저장.** 부분 실패, 중복 요청, 오래된 스냅샷, 다른 기기 동시 수정에서 서버 데이터가 맞는지 확인한다. 주문을 바꾼 경우 생산 가능 여부, 이전 주문, 방문 지원, 보상 중복을 검사한다.
5. **그래픽과 접근성.** 작은 화면에서 HUD와 타이머가 주요 물체를 가리지 않고, 음소거·동작 줄이기에서도 플레이에 필요한 상태를 확인할 수 있어야 한다. 가능하면 실제 스마트폰에서 첫 화면과 확장 농장의 반응을 확인하고, 기기와 조건을 결과에 적는다. 에뮬레이션 결과는 별도로 기록한다.
6. **자동 검증.** `npm test`와 `npm run build`를 실행한다. 게임 규칙, 입력, 저장에 새 동작이 생겼다면 기존 테스트가 잡지 못하는 회귀를 검사한다. 저장 SQL을 바꾼 경우 `tests/open-farm.sql` 관련 시나리오를 검증용 DB에서 확인한다. 모델을 바꾼 경우 출처, 해시, 라이선스 고지를 함께 확인한다.
7. **인계 결과.** 바뀐 플레이 동작, 테스트 결과, 화면 전후 비교, 아직 검증하지 못한 사항을 요약한다. 구현한 항목만 체크한다.
